Low fidelity, mobile. One occasion page per occasion, localized per market (TR: Evleniyor musun? / Nişan-kına / Doğum günü; IT: Ti sposi? / Comunione / Compleanno; UK: Getting married? / Birthday / Hen party). Every service opens its OWN existing request flow: no basket, no "request all", no change to the request flow or pricing. [Brackets] = placeholders. Service order on the page comes from measured co-need and is updated by the post-submit card data.

Why A

Closest to real service benchmarks (Thumbtack groups party services by theme with average prices).

Each card = one existing request flow. Price range and pro count come from data Armut already shows.

"Talep edildi" state turns the page into a light checklist without a basket.

Effort: FE 1-2 wks, UX 1 wk, BE config + tracking.

Risk: section names imply an order; keep them neutral until data shows real booking order.

Why / why not B

Closest to Getir's "recipe -> ingredients" idea and Getir's ready basket ("Hazır Sepet").

The tick is explicit intent, so fewer low-intent requests than a "request all" button.

But: Armut has no basket: 3 ticks = 3 full request flows in a row. Long, and pros pay per quote, so abandoned or half-hearted requests cost them.

Percentages are design notes, not shown to users.

Use: test later, once A works; or let the ticks save a "my list" without sending requests.

Why / why not C

Matches planner apps (wedding checklists) and helps first-time planners.

But: our own data shows most requests are near-date and small (median ~7 days for photographers in TR samples; similar in IT). A months-ahead timeline fits planners, not most of our users.

Reminders need messaging consent.

Use: a later variant for "Evleniyor musun?" only, if data shows long-lead planners.

Test

Phase 1: Option A in TR (İstanbul, Ankara, İzmir) and one IT city, before peak season. Arms: control (today) / homepage tile -> occasion page / tile -> search overlay with the event block. Primary: submitted event requests per exposed visitor. North star: event requests with 1+ quote in 48h. Also: share sending 2+ event requests in 30 days. Guardrails: total requests per visitor, 0-quote share, pro complaints. Phase 2: Option B ticks as a variant of A.
